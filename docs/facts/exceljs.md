# exceljs 4.4.0 behaviour reproduced by @xlvane/exceljs

Ids `X4-*` are cited from `packages/exceljs/src`. Every fact was read in the exceljs 4.4.0 source as installed in `bench/node_modules/exceljs` (`npm ci --prefix bench`; the package's `lib/` is the published source) on 2026-10-30, and where noted confirmed by running it. Paths are relative to the package root. Ported tests are in `tests/exceljs/` (README there).

### X4-01 — Format codes written as built-in ids
`StylesXform._addNumFmtStr(formatCode)` (`lib/xlsx/xform/style/styles-xform.js` L374–386) first looks the code up with `NumFmtXform.getDefaultFmtId` (`lib/xlsx/xform/style/numfmt-xform.js` L55), a hash of the `f` codes of `lib/xlsx/defaultnumformats.js` (ids 0–4, 9–22, 37–40, 45–49; the locale-dependent ids 27–36 and 50–81 have no `f`). A matching code is written as that id with no `numFmt` element; any other code gets a custom id from 164.

### X4-02 — Dates without a format get built-in format 14
`StylesXform.addStyleModel(model, cellType)` (`styles-xform.js` L245–266): without `model.numFmt`, a Number cell gets `General` and a Date cell `mm-dd-yy`, which X4-01 turns into id 14. The cell type is the type of the formula result for formula cells (`getEffectiveCellType`, `lib/xlsx/xform/sheet/cell-xform.js` L36–43). The mock used by the streaming writer without `useStyles` (`styles-xform.js` L495–515) still gives Date cells a style with `numFmtId` 14 (`dateStyleId`). Confirmed by running exceljs: a Date cell is written `<xf numFmtId="14" …>` and reads back with `numFmt` `"mm-dd-yy"`.

### X4-03 — Document property defaults
- `Workbook` constructor (`lib/doc/workbook.js` L15–31): `category`, `company`, `description`, `keywords`, `manager`, `subject`, `title` are `''`; `created = new Date()`, `modified = created`; `creator`, `lastModifiedBy`, `lastPrinted` are not set.
- `Workbook.model` getter (L153–180): `creator` and `lastModifiedBy` default to `'Unknown'`; the model also carries `language`, `revision`, `contentStatus`.
- `XLSX.prepareModel` (`lib/xlsx/xlsx.js` L594–600): `created` and `modified` default to now when unset.
- `CoreXform` (`lib/xlsx/xform/core/core-xform.js` L12–60): writes an element unless the value is `undefined`; `cp:revision` is an `IntegerXform`, so it reads back as a number (L22); reading returns `creator`, `title`, `subject`, `description`, `identifier`, `language`, `keywords`, `category`, `lastModifiedBy`, `lastPrinted`, `revision`, `contentStatus`, `contentType`, `created`, `modified` (L99–114).
- Reading (`xlsx.js` L345–358, `workbook.js` model setter L182–198): every property is assigned from the file, so a missing one becomes `undefined`; `company` and `manager` come from `docProps/app.xml`.
- `stream.xlsx.WorkbookWriter` (`lib/stream/xlsx/workbook-writer.js` L22–30): options `created` (default now), `modified` (default `created`), `creator` and `lastModifiedBy` (default `'ExcelJS'`), `lastPrinted`; `addCore` (L264–271) writes them with `CoreXform`.

### X4-04 — Columns that are written
`Column.toModel` (`lib/doc/column.js` L265–293): a column is skipped when `isDefault` (L147–162: no custom width — width unset or 9 —, not hidden, no outline level, and no `font`, `numFmt`, `alignment`, `border`, `fill` or `protection` in its style); otherwise it is written with `width` defaulting to 9 (`DEFAULT_COLUMN_WIDTH`, L8) and its style. New cells inherit the column style with the row style winning per property (`lib/doc/cell.js` L27, `_mergeStyle` L99). Reading turns `col@style` back into the column's style (`lib/xlsx/xform/sheet/col-xform.js` L53, L80–81). Confirmed by running exceljs: a styled column without width is written `<col min="5" max="5" width="9" style="1" customWidth="1"/>`.

### X4-05 — Defined names are cell sets
`DefinedNames` (`lib/doc/defined-names.js`) keeps one `CellMatrix` (`lib/utils/cell-matrix.js`) per name: sheet → row → column. `add(locStr, name)` decodes the location with `colCache.decodeEx` (`lib/utils/col-cache.js` L216–257) and adds every cell of a range (L21–44); `remove`/`removeEx` delete one cell; `removeAllNames` deletes a cell from every name; `getNames`/`getNamesEx` list the names that hold a cell (L71–79). `Cell.name`, `names`, `addName`, `removeName`, `removeAllNames` and `fullAddress` work on these (`lib/doc/cell.js` L270–310).

### X4-06 — Ranges of a name
`getRanges(name)` (`defined-names.js` L81–145) marks every cell and grows rectangles from each unmarked one, first down and up in the column, then left and right over the rows found; each rectangle is written as `$shortRange` (`lib/doc/range.js` L204–214): `Sheet!$A$1` for one cell, `Sheet!$A$1:$B$2` otherwise. The sheet prefix is unquoted when the sheet name matches `/^[a-zA-Z0-9]*$/`, else quoted with single quotes, without doubling quotes inside (`range.js` L153–160). `model` lists `{ name, ranges }` for names with at least one range (L175–180).

### X4-07 — Writing and reading names
Writing: each model entry becomes `<definedName name="…">` with the ranges joined by commas and no `localSheetId` (`lib/xlsx/xform/book/defined-name-xform.js` L5–16); print areas and titles of `pageSetup` are added as `_xlnm.Print_Area` / `_xlnm.Print_Titles` (`lib/xlsx/xform/book/workbook-xform.js` L37–90). Reading: `extractRanges` (`defined-name-xform.js` L55–89) splits the text on commas, keeping quoted sheet names together, and keeps parts `colCache.decodeEx` accepts; `_xlnm.Print_Area` and `_xlnm.Print_Titles` move to `pageSetup` (`workbook-xform.js` L187–232); `localSheetId` is read but not used by the model; the `model` setter keeps only ranges whose address part matches `/[$](\w+)[$](\d+)(:[$](\w+)[$](\d+))?/` (`defined-names.js` L8, L182–193), and two entries with the same name replace each other.

### X4-08 — Splicing names
`DefinedNames.spliceRows` / `spliceColumns` (`defined-names.js` L147–173) splice each matrix (`cell-matrix.js` L138–162) and renumber the moved cells (`normaliseMatrix`).

### X4-09 — Rich text values
`RichTextValue` (`lib/doc/cell.js` L494): `{ richText: [{ text, font? }] }`, type `RichText`, text the run texts joined (`toString`, L511–513). Written as a shared string item with `<r><rPr>…</rPr><t>` runs (`lib/xlsx/xform/strings/shared-string-xform.js` L31–45, `lib/xlsx/xform/strings/rich-text-xform.js` L36); the run font uses `rFont` for `name` (`rich-text-xform.js` L98, `fontNameTag`) and the other properties as for cell fonts (`lib/xlsx/xform/style/font-xform.js` L19–34). Reading builds `{ richText }` again (`shared-string-xform.js` L71–80); runs without `rPr` have no `font`. Confirmed by running exceljs: 6-digit `argb` colours are written and read back unchanged.

### X4-10 — Hyperlink values
`Value.getType` (`lib/doc/cell.js` L1078): a value is a hyperlink when `value.text && value.hyperlink` are both truthy. `HyperlinkValue` (L582–666): `value` is `{ text, hyperlink }` plus `tooltip` when truthy; `toString`/`cell.text` is the text (L664); `cell.hyperlink` is the target (L201). Writing (`lib/xlsx/xform/sheet/cell-xform.js` L80–89): the text goes to the shared string table and `{ address, target, tooltip }` to the sheet's link list; every link gets its own relationship with `TargetMode="External"` (`lib/xlsx/xform/sheet/worksheet-xform.js` L158–167), and `location` is added only when the target matches `/^[^!]+![a-zA-Z]+[\d]+$/` (`lib/xlsx/xform/sheet/hyperlink-xform.js` L8–23, L50). Reading (`worksheet-xform.js` L469–474, `cell-xform.js` L477–489): only links with `r:id` are used, the target is the relationship's `Target`, `location` and `tooltip` are ignored, and the cell becomes `{ text, hyperlink }` with the value (or the formula result) as text. Confirmed by running exceljs: `#Sales!C5` reads back as `#Sales!C5`.

### X4-11 — Sheet views
`SheetViewXform.render` (`lib/xlsx/xform/sheet/sheet-view-xform.js` L26–99) writes `rightToLeft`, `showRowColHeaders`, `showGridLines` only when they differ from the defaults, `zoomScale`, `zoomScaleNormal` and `view` (from `style`) when set; a frozen view gets `pane` with `topLeftCell` (default: the first cell below and right of the split) and `state="frozen"`, a split view a `pane` with `xSplit`/`ySplit` as given (1/20 point) and no `state`. `parseClose` (L145–192) returns for every `sheetView` an object with `workbookViewId`, `rightToLeft`, `state` (`normal`, `frozen`, or `split` for a pane without a frozen state), `showRuler`, `showRowColHeaders`, `showGridLines`, `zoomScale` and `zoomScaleNormal` (100 when absent), `xSplit`/`ySplit`/`topLeftCell` for a pane, `activePane` for a split (default `topLeft`), `activeCell` from the selection of the active pane, and `style` when `view` is set. The spec `spec/integration/workbook/workbook.spec.js` (exceljs v4.4.0, "frozen panes", "serialises split panes") shows the read-back objects.

### X4-12 — Tab colour
`worksheet.properties.tabColor` (`lib/doc/worksheet.js` L51–60; the deprecated `worksheet.tabColor`, L827–837, reads and sets it) is written as `<sheetPr><tabColor …/></sheetPr>` with `rgb` from `argb`, or `theme` and `tint`, or `indexed` (`lib/xlsx/xform/sheet/sheet-properties-xform.js` L21–38, `lib/xlsx/xform/style/color-xform.js` L16–35) and read back into `properties.tabColor` (`worksheet-xform.js` L394–400, `color-xform.js` L37–54).

### X4-13 — Company and manager
`AppXform.render` (`lib/xlsx/xform/core/app-xform.js` L20–37) writes `Application` "Microsoft Excel", `DocSecurity`, `ScaleCrop`, `HeadingPairs`, `TitlesOfParts`, `Company` as `model.company || ''` (always), `Manager` when not `undefined`, and `AppVersion` "16.0300". Reading takes only `company` and `manager` (`lib/xlsx/xlsx.js` L345–349), so they are `undefined` when the part or element is missing. The streaming `WorkbookWriter` does not take `company` or `manager` (X4-03).

### X4-14 — Notes
`cell.note` stores a `Note` (`lib/doc/cell.js` L224–230). `Note.model` (`lib/doc/note.js`) turns a string into `{ texts: [{ text }] }` and deep-merges `DEFAULT_CONFIGS` (`margins` `{ insetmode: 'auto', inset: [0.13, 0.13, 0.25, 0.25] }`, `protection` `{ locked: 'True', lockText: 'True' }`, `editAs: 'absolute'`); `set model` gives back a string when `texts` has one entry with only `text`. `CommentsXform.render` (`lib/xlsx/xform/comment/comments-xform.js` L22–40) writes one author, "Author", and `CommentXform.render` (`comment-xform.js`) writes every comment with `authorId="0"` and its `texts` as rich text runs. On reading, the VML shape settings are merged into the note by index (`lib/xlsx/xform/sheet/worksheet-xform.js` L450–468), and a note is attached only to a cell that exists in the sheet data (`cell-xform.js` L491–494; a cell with only a note is not written, `cell-xform.js` L200). The streaming `WorkbookWriter` writes notes (`lib/stream/xlsx/sheet-comments-writer.js`); the streaming reader has no comment handling (no `comment` in `lib/stream/xlsx/worksheet-reader.js` or `workbook-reader.js`). Confirmed by running exceljs 4.4.0 on the sample project: `'Checked by finance'` reads back as a string, a two-run note as `{ texts }` with the runs as written.

### X4-15 — Row and column splicing
Read in `lib/doc/worksheet.js` and `lib/doc/row.js` of exceljs 4.4.0 and confirmed by running it in memory (phase B exploration, 2026-10-30).
- **API.** `insertRow(pos, value, style = 'n')` (L422–426) is `spliceRows(pos, 0, value)` followed by `_setStyleOption(pos, style)` and returns `getRow(pos)`; `insertRows(pos, values, style = 'n')` (L428–441) splices all values, copies styles per inserted row and returns `getRows(pos, values.length)`. `addRow(value, style)` (L406–412) passes only `i` options on. Style options (README L859, L961; `_setStyleOption` L444–450, `_copyStyle` L452–461): `n` none, `i` from the row above, `o` from the row below, `+` also for empty cells; the copy covers the row style, the cell styles and the height.
- **`duplicateRow(rowNum, count, insert = false)`** (L463–481): the code default of `insert` is `false`; the README (L992) says `true`. The copies get `rSrc.values`, then the same style objects (shared) and the height.
- **`spliceRows(start, count, ...inserts)`** (L483–548): copies `values`, `style`, `height` and cell styles from row object to row object; inserted rows get `style = {}`; slave cells below an insert are re-merged with their master moved by the number of inserts (L525–531); `definedNames.spliceRows` is called at L547. Not moved: formula text, `ws._merges`, notes (the cells are rebuilt from `values`), the hidden flag and outline level, data validations, conditional formatting, the autofilter and tables. Removing more rows than follow the removed block leaves rows behind (the move loop does not run).
- **`spliceColumns(start, count, ...inserts)`** (L264–307): calls `row.splice` for each row up to the row count taken before the loop with `insert[i] || null` (falsy values become `null`), moves column definitions through `defn` (whose setter writes the header into row 1 again, `lib/doc/column.js` L79–87), gives inserted columns `defn = null`, and calls `definedNames.spliceColumns` (L306).
- **`row.splice(start, count, ...inserts)`** (`lib/doc/row.js` L77–127): moves values, styles and notes (`_comment`) between cell objects; cells left at the end get `null` and style `{}`.
- **Streaming.** `lib/stream/xlsx/worksheet-writer.js` defines none of `insertRow`, `insertRows`, `spliceRows`, `duplicateRow`, `spliceColumns` (calling one is a `TypeError`); its rows use `lib/doc/row.js`, so `row.splice` exists.
- **Defined names** move with `DefinedNames.spliceRows`/`spliceColumns` (X4-08); cells inserted inside a name are not added to it.

### X4-16 — Data validations
Read in exceljs 4.4.0 and confirmed by writing and reading workbooks in memory (phase C research, 2026-10-30).
- **Model.** `DataValidations` (`lib/doc/data-validations.js`) is a plain object keyed by address: `add(address, v)` sets `model[address] = v`, `find(address)` is an exact key lookup, `remove(address)` sets the entry to `undefined` (the key stays). `cell.dataValidation` (`lib/doc/cell.js` L314–324) reads and writes the entry of the cell's own address, so a range key (`'E1:E5'`) is not found for `E3` before the file is saved.
- **Write** (`lib/xlsx/xform/sheet/data-validations-xform.js` L24–163): equal single-cell entries (`_.isEqual`) are merged into rectangles, downwards then rightwards; `matchCol` (L32–40) does not check cells already used, so the ranges can overlap (A2, B1 and B2 give `A2:B2` and `B1:B2`). `type` is written unless it is `any`; `operator` unless it is `list` or `between`; `allowBlank="1"` only for typed validations; the messages and `errorStyle` only when truthy; `formula1`/`formula2` from `formulae`, dates through `dateToExcel`, other values as given. An `undefined` entry (after `remove`) is written as `<dataValidation sqref="…"/>`.
- **Read** (L165–264): a missing `type` is `any`; `allowBlank` only with a type; `operator` defaults to `between` except for any, list and custom; without formulae both `formulae` and `operator` are deleted; `formula1`/`formula2` are typed per type (whole and textLength `parseInt`, decimal `parseFloat`, date `excelToDate`, others strings); every cell of every range in `sqref` gets the same validation object.
- `errorStyle` is not checked (the data of `spec/utils/data/data-validations.json` uses `"error"`), and a decimal validation without `formulae` is written without a formula.

### X4-17 — Conditional formatting
- **API.** `addConditionalFormatting(cf)` pushes `{ ref, rules }` on `worksheet.conditionalFormattings`; `removeConditionalFormatting(filter)` splices an index, filters with a function or clears the list (`lib/doc/worksheet.js` L811–822).
- **Write** (`lib/xlsx/xform/sheet/cf/conditional-formattings-xform.js` L20–37, `cf-rule-xform.js` L119–267): rules without a priority get `nextPriority++` starting at the highest given priority (not one above it), so priorities can repeat; each styled rule gets its own `dxf` (`styles-xform.js` L346–354, not deduplicated). containsText rules are written with `type` = their `operator` and no `text` attribute; without an operator the rule has no type. When `formulae` are not given, `getTextFormula` (L18–39) and `getTimePeriodFormula` (L41–72) generate them from the top-left cell of `ref` (`NOT(ISERROR(SEARCH("<text>",A1)))` with the text inserted unescaped, `LEN(TRIM(A1))=0`, `FLOOR(A1,1)=TODAY()`, …). top10 always writes `rank` (default 10). Data bars without `gradient: true`, custom icon sets and 3Triangles, 3Stars, 5Boxes go to the x14 `extLst` with a random `x14:id` (`cf-ext/cf-rule-ext-xform.js` L41–45). The icon set default is called `3TrafficLights` and not written (`icon-set-xform.js` L19–31).
- **Read** (`cf-rule-xform.js` L269–280; `conditional-formattings-xform.js` L80–89): text rule types read back as `{ type: 'containsText', operator: <type> }`; `dxfId` becomes `style`, whose `numFmt` is an object `{ id, formatCode }`; writing that style again gives `formatCode="[object Object]"`. cfvo `val` is read with `parseFloat`; formulae are strings.

### X4-18 — Sheet protection
`protect(password, options)` (`lib/doc/worksheet.js` L753–787) returns a Promise; it sets `sheetProtection = { sheet: true }`, with a password adds `algorithmName` SHA-512, a random 16-byte `saltValue`, `spinCount` (default 100000) and `hashValue`, then assigns the options (`spinCount` is deleted without a password). `SheetProtectionXform` (`lib/xlsx/xform/sheet/sheet-protection-xform.js` L17–82) writes `sheet="1"`, `selectLockedCells`/`selectUnlockedCells` `"1"` when the option is `false`, `formatCells` … `pivotTables` `"0"` when the option is `true`, and `objects`/`scenarios` `"1"` when they are `false`; reading inverts this, leaving unset keys `undefined`. `unprotect()` sets `sheetProtection = null`.

### X4-19 — Page setup, header and footer, page breaks, print area and titles
- **Defaults** (`lib/doc/worksheet.js` L64–106): margins 0.7/0.7/0.75/0.75/0.3/0.3, `orientation` portrait, dpi 4294967295, `fitToPage` computed once in the constructor (`(fitToWidth || fitToHeight) && !scale` of the options), `cellComments` `'None'`, `errors` `'displayed'`, scale 100, fitTo 1; `headerFooter` with `null` texts. Page margins and page setup are written for every sheet (`worksheet-xform.js` L337–339).
- **pageSetup** (`lib/xlsx/xform/sheet/page-setup-xform.js` L18, L43–89): `cellComments` is written only for `atEnd` and the misspelled `asDisplyed`; reading fills `firstPageNumber` 1, `copies` 1, `useFirstPageNumber`, `usePrinterDefaults` and `cellComments` `'None'`.
- **Row breaks.** `row.addPageBreak(lft, rght)` (`lib/doc/row.js` L150–162) pushes `{ id: rowNumber, max: (rght − 1) || 16838, man: 1, min? }` on `worksheet.rowBreaks`; the reader never fills `rowBreaks` (`page-breaks-xform.js` L14 reads a `ref` attribute that `brk` does not have).
- **Print area and titles** (`lib/xlsx/xform/book/workbook-xform.js` L37–84, L187–231): `printArea` (areas joined by `&&`) is written as one `_xlnm.Print_Area` name per area, `printTitlesRow`/`printTitlesColumn` as one `_xlnm.Print_Titles` name; the sheet name is quoted without doubling an apostrophe. Reading takes the first range of each print area name, finds titles by the forms `$n:$m` and `$A:$B` and strips `$`, and removes these names from `definedNames`.

### X4-20 — x14 data bars and icon sets
- **Which rules use the extension** (`lib/xlsx/xform/sheet/cf-ext/cf-rule-ext-xform.js` L8–41): a dataBar is an extension rule when `!rule.gradient` (`databar-ext-xform.js` L24–28); an iconSet when `custom` is set or the set is 3Triangles, 3Stars or 5Boxes. The x14 id is a random `{UUIDV4}` in upper case (L41–45). The x14 dataBar rule has no priority; the x14 iconSet rule has one (L60–80).
- **x14 data bar** (`databar-ext-xform.js` L34–62, L64–81): attributes `minLength` (default 0) and `maxLength` (default 100) always written; `border` (false), `gradient` (true), `negativeBarColorSameAsPositive` (true), `negativeBarBorderColorSameAsPositive` (true), `axisPosition` (`'auto'`), `direction` (`'leftToRight'`) written only when they differ from these defaults; colour elements `borderColor`, `negativeBorderColor`, `negativeFillColor`, `axisColor` written whenever given, in that order. The same defaults fill the model on read. So a bar without `gradient` has no `gradient` attribute and is a gradient bar, and no axis colour is written by default. Observed with exceljs 4.4.0 `writeBuffer` and `load` (scratch script, 2026-10-30): the read rule carries `x14Id`, the lengths, `border`, `gradient`, both `…SameAsPositive` flags, `axisPosition` `'auto'`, `direction` `'leftToRight'` and the given colours; its `cfvo` comes from the main element.
- **x14 icon set** (`icon-set-ext-xform.js` L21–70, `cf-icon-ext-xform.js`): `custom="1"` is written when `icons` is given, and every icon's `iconId` is replaced by its position (`icon.iconId = i`, L33–36); on read `icons` is filled but `custom` is not (the model has no `custom` field), so `cf-rule-xform.js` `isPrimitive` treats a read custom rule as a main rule when it is written again.
- **Merging on read** (`lib/xlsx/xform/sheet/worksheet-xform.js` L34–89): an extension rule with the `x14Id` of a main rule is merged into it (fields the main rule lacks); other extension rules are added to the last range read with the same reference, or form a new range.
