## Tables (D-D02)

Sources for TD-01 … TD-12: R3 Items 9–11, 14(D) (P1 §12.3.21, §18.5, §18.3.1.94/.95, §18.3.2, Annex G.1; OI §2.1.679 … §2.1.684, §2.1.1094, §3.2.3.1.1); S-XSD = `spec/ECMA-376-4_5th_edition_december_2016/xsd/sml.xsd` (Transitional) and the Strict copy in `spec/ECMA-376-1_supporting/OfficeOpenXML-XMLSchema-Strict/sml.xsd`; observations in the POI corpus (files saved by Excel) and LibreOffice 24.2.7.2.

### TD-01 - Table Definition part - VERIFIED
Content type `application/vnd.openxmlformats-officedocument.spreadsheetml.table+xml`; root element `table`; Transitional relationship `http://schemas.openxmlformats.org/officeDocument/2006/relationships/table` (P4 §10.2.21), Strict `http://purl.oclc.org/ooxml/officeDocument/relationships/table`; one part per table, the target of a relationship from the Worksheet part, internal. Source: P1 §12.3.21 p.96–97 (R3 Item 9.1). P1 calls the relationship implicit, while the sheet names it with `tablePart r:id` (§18.3.1.94), the explicit mechanism of §9.2 (R3 Item 9, finding 1); the reader therefore reads every `table` relationship of the sheet, and the writer writes both. Excel names the parts `xl/tables/tableN.xml` (POI corpus).

### TD-02 - CT_Table and its order - VERIFIED
CT_Table: `autoFilter?`, `sortState?`, `tableColumns`, `tableStyleInfo?`, `extLst?`; required `id`, `displayName`, `ref`; `name` optional; `headerRowCount` default 1, `totalsRowCount` default 0, `totalsRowShown` default true. CT_TableColumn: `calculatedColumnFormula?`, `totalsRowFormula?`, `xmlColumnPr?`, `extLst?`; required `id`, `name`; `totalsRowFunction` default `none`. Source: S-XSD T3945–4047 / Strict 3916–4018 (identical, R3 Item 10). In CT_Worksheet `tableParts` comes after `picture` and before `extLst` (S-XSD T2210). `tableParts@count` is the number of `tablePart` elements (P1 §18.3.1.95).

### TD-03 - Names - VERIFIED
`displayName` is the name used in formulas: no spaces, unique among all `displayName`s and defined names of the workbook, same characters and lengths as defined names (P1 §18.5.1.2), i.e. the name grammar of §18.17.2.5 (letter, `_` or `\` first; letters, digits, `_`, `.`; not case-sensitive; not TRUE/FALSE or a cell reference). `name` is the object-model name, unique per table per sheet, by default equal to `displayName`; Office uses `displayName` when `name` is empty or missing (OI §2.1.680 c). Table `id`: non-zero, unique per workbook (P1); Office: 1 … 4294967294 (OI §2.1.680 a). Source: R3 Items 10.3, 10.7, 14(D). Implementation: xlvane applies the defined-name rules of D-A03 (also `?` and characters above U+007F, as for defined names) to both names and compares them with all table and defined names ignoring case.
**D-D05:** the built-in names of P1 §18.2.5 (Print_Area, Print_Titles, Criteria, _FilterDatabase, Extract, Consolidate_Area, Database, Sheet_Title; W2-06), with or without `_xlnm.`, and any `_xl` prefix are refused as table names. A table must not overlap the sheet filter ([MS-OI29500] §2.1.680 h): `addTable`, `autoFilter` and the streaming writer (where `autoFilter: true` covers every used cell) refuse it.

### TD-04 - Limits - VERIFIED
`name` at most 255 characters (OI §2.1.680 b); column `name` at most 255 (OI §2.1.681 a); `totalsRowLabel` at most 32767 (OI §2.1.681 j); `comment` at most 255 (OI §2.1.680 g); tableStyleInfo `name` 1 … 255 (OI §2.1.682 a). Column `id` greater than 0 (OI §2.1.681 h). Source: R3 Item 14(D). Column names are unique per table (P1 §18.5.1.3); xlvane compares them ignoring case (implementation choice, the safe side).

### TD-05 - Header and totals rows - VERIFIED
`headerRowCount` and `totalsRowCount` count rows shown at the top and bottom, 0 = not shown, normally at most 1 (P1 §18.5.1.2). `ref` "shall include the totals row if it is shown"; that it includes the header row is not stated in P1, but every P1 example and OI §2.1.680 h (rows of `ref` ≥ headerRowCount + insertRow + totalsRowCount) imply it. `totalsRowShown` means the totals row "has ever been shown"; Office requires it to be true when `totalsRowCount` is 1 (OI §2.1.680 f). In Office the text of a header cell equals the column `name` (OI §2.1.681 i); P1 has no such rule. Source: R3 Items 10.3, 10.7, 14(D). Implementation: a table without totals row is written with `totalsRowShown="0"`, as in 40 of the 57 table parts without totals row in the POI corpus (for example `50867_with_table.xlsx`, `55745.xlsx`; the other 17 omit the attribute; observation); with a totals row the attribute is left at its default true.

### TD-06 - Totals functions - VERIFIED
ST_TotalsRowFunction: none, sum, min, max, average, count, countNums, stdDev, var, custom (P1 §18.18.83). `custom` uses `totalsRowFormula`, and then `totalsRowFunction` shall be `custom` (P1 §18.5.1.6). `totalsRowLabel` is shown only with `none`; Office requires it absent with `custom` (P1 §18.5.1.3; OI §2.1.681 c). The other functions are `SUBTOTAL(n, ref)` in the totals cell with n = average 101, countNums 102, count 103, max 104, min 105, stdDev 107, sum 109, var 110, and the reference designating the column's data cells (OI §2.1.1094, §2.1.681 n). Source: R3 Items 10.5, 10.6, 14(D).

### TD-07 - Column references in totals formulas - VERIFIED (grammar) / observation (form)
Structured references: `table-name[column-name]` and `table-name[[column-name]]` both mean the data cells of a column; inside a column name `'`, `[`, `]` and `#` are escaped by a preceding `'`; a simple column name cannot start or end with a space (OI §3.2.3.1.1, R3 Item 14(b)). Observation (POI corpus, files saved by Excel): totals cells hold `SUBTOTAL(109,BigCity[Population])` (`DataTableCities.xlsx`) and, for a column named `Field 4 ` with a trailing space, `SUBTOTAL(109,Tabelle1[[Field 4 ]])` (`table-sample.xlsx`). Implementation: single brackets, double brackets when the name has a leading or trailing space or one of the four escaped characters.

### TD-08 - Autofilter of a table - observation
P1 has no rule relating the table's `autoFilter@ref` to its `ref`; in every P1 example they are equal (R3 Item 11, AutoFilter of a table), and in Office a table's `ref` must not overlap another table or autofilter of the sheet (OI §2.1.680 h). Observation: the tables with a totals row that Excel saved in the POI corpus have an `autoFilter` covering the header and data rows only (`DataTableCities.xlsx` C2:F15 / C2:F14, `bug66215.xlsx` B3:F7 / B3:F6, `table-sample.xlsx` C4:G9 / C4:G8, `tableStyle.xlsx` B2:E7 / B2:E6); xlvane writes it that way. A hidden filter button is `filterColumn@hiddenButton="1"` (CT_FilterColumn, S-XSD T24–37).

### TD-09 - Table styles - VERIFIED
`tableStyleInfo@name` names a table style; if it names none, the application should use its default style (P1 §18.5.1.5). The built-in table styles are TableStyleLight1 … 21, TableStyleMedium1 … 28 and TableStyleDark1 … 11 (P1 Annex G.1 p.4416; `presetTableStyles.xml` of the Part 1 supporting archive, checked: 60 table styles besides the pivot styles). Office's defaults for the four `show…` attributes are false (OI §2.1.682 b–e). Implementation: only the 60 built-in names (or none) can be written; the default is `TableStyleMedium2` with all `show…` false, the defaults of exceljs 4.4.0 (`lib/doc/table.js` `validate`, X4 research).

### TD-10 - LibreOffice - observation
LibreOffice 24.2.7.2 re-saves a table written by xlvane with the same `ref`, columns, `totalsRowCount` and totals functions and calculates the SUBTOTAL totals; it does not write back `tableStyleInfo` or `totalsRowLabel` (the label stays in the cell), and its `autoFilter` then covers the totals row too (`tests/libreoffice/tables.test.ts`).

### TD-11 - Tables and row insertion - implementation choice
The table range and its autofilter follow inserted and deleted rows as ranges do (D-B01, R-03 … R-17): rows inserted inside the table, also directly above its totals row, make it grow; a table below the inserted rows moves. Formulas of calculated columns and totals are adjusted like cell formulas; structured references need no adjustment (OI §3.2.3.1.1: "They need no adjustment when the referenced tables are modified"). Deleting rows that contain a table's header row, its totals row or all of its data rows is refused, because the table would lose a part P1 counts in `ref` (TD-05).
**D-D05:** a table filter in the form of TD-08 (header and data rows) is derived from the table range after the change, so rows inserted just above the totals row join the filter; other filter ranges move as ranges do.

### TD-12 - readTable by table name - implementation choice
`readTable(file, { table })` finds the table by `displayName` or `name` ignoring case (names are not case-sensitive, P1 §18.17.2.5), reads the header row and the data rows of `ref`, and leaves the totals row out.

## Pictures (D-D03)

### TD-30 - Drawings part - VERIFIED
Content type `application/vnd.openxmlformats-officedocument.drawing+xml`; root `wsDr` in `http://schemas.openxmlformats.org/drawingml/2006/spreadsheetDrawing` (Transitional, P4 §10.2.8) or `http://purl.oclc.org/ooxml/drawingml/spreadsheetDrawing` (Strict); relationship type `…/officeDocument/2006/relationships/drawing` (Transitional). Target of an **explicit** relationship from the worksheet, at most one Drawings part per worksheet, internal; it may have explicit relationships to Images (§15.2.14) and Hyperlinks (§15.3), among others (charts, diagrams, content parts). The worksheet names it with `drawing r:id` (P1 §18.3.1.36, P4 §15.10.8). Sources: R3 Item 9.2 (P1 §12.3.8, p.77–79, L3685–L3763), Item 11; P1 §12.3.24 (worksheet explicit relationships, L4899–L4921). Implementation: `readSheetDrawing` follows the `drawing` element's `r:id`; the writer writes `xl/drawings/drawingN.xml`, numbered across the workbook, with an Override content type.

### TD-31 - Image parts and formats - VERIFIED (formats) / OBSERVED (signatures)
P1 §15.2.14 (R3 Item 9.3, raw L5682–L5709): content type "Any supported image type"; the note names `image/gif`, `image/png`, `image/tiff`, `image/pict`, `image/jpeg`; "A producer that wants interoperability should use" `image/png` or `image/jpeg`. Relationship type `…/relationships/image` (Transitional, P4 §13.2.14). OI §2.1.33 adds `image/emf`, `image/emf+`, `image/wmf` (R3 Item 14 (D)). xlvane writes PNG, JPEG and GIF (maintainer's decision) as `xl/media/imageN.<png|jpeg|gif>`, each distinct image once, with an Override content type per part. **Signatures** (the PNG, JPEG and GIF specifications were not reachable from the session; network refused): observed in the image parts of the POI corpus on 2026-10-30 - PNG `89 50 4E 47 0D 0A 1A 0A` (9 parts), JPEG `FF D8 FF E0 00 10 4A 46` (11 parts; xlvane checks `FF D8 FF`), EMF `01 00 00 00 …`, WMF `D7 CD C6 9A …` - and in the GIF files shipped with LibreOffice (`/usr/lib/libreoffice/share/gallery/*.gif`: `GIF87a`, `GIF89a`). Reading reports other formats with `format: null` and keeps their bytes.


### TD-31a - EMF and WMF parts written back - OBSERVED (2026-10-31, D-R01)
In `tests/corpus/poi/WithDrawing.xlsx` (app.xml: Microsoft Excel) and `49156.xlsx`, `[Content_Types].xml` declares `<Default Extension="emf" ContentType="image/x-emf"/>` and `<Default Extension="wmf" ContentType="image/x-wmf"/>`; the EMF parts start with `01 00 00 00` and have ` EMF` (`20 45 4D 46`) at offset 40, the WMF parts start with `D7 CD C6 9A`. Implementation: `addImage` accepts bytes with these signatures and writes them as `xl/media/imageN.emf` / `.wmf` with those content types; reading still reports `format: null` for them. NOT CHECKED: the EMF and WMF specifications ([MS-EMF], [MS-WMF]) and non-placeable WMF files.

### TD-32 - Anchors and markers - VERIFIED (schema) / INFERRED (0-based)
`dml-spreadsheetDrawing.xsd` (Transitional): CT_TwoCellAnchor L147 (`from`, `to`, object, `clientData`; `editAs` default `twoCell`), CT_OneCellAnchor L156 (`from`, `ext`, object, `clientData`; no `editAs`), CT_AbsoluteAnchor L164 (`pos`, `ext`, …), CT_Marker L132 (`col`, `colOff`, `row`, `rowOff`), ST_ColID/ST_RowID L122/L127 (`int`, minimum 0), EG_ObjectChoices (`sp`, `grpSp`, `graphicFrame`, `cxnSp`, `pic`, `contentPart`). `editAs` (P1 §20.5.2.33, §20.5.3.2, R3 Item 12): how the object follows resizing and insertion of rows/columns between or before its anchors; `twoCell` moves and resizes, `oneCell` moves only, `absolute` keeps size and position. OI §2.1.1361 / §2.1.1370: Excel's maximum column 16383, row 1048575; OI §2.1.1365: `from` must not be below or right of `to`, else the shape is not shown; OI §2.1.1362: offsets above 20454781742437 are not drawn. No document says the indices are 0-based (R3 searched); minimum 0 with these maxima fits 0-based indices (inference), and every POI file agrees (B2 is `col 1, row 1`). `colOff`/`rowOff` are ST_Coordinate: EMU or a universal measure (`mm`, `cm`, `in`, `pt`, `pc`, `pi`; R3 Item 12); xlvane reads EMU, `in`, `cm`, `mm`, `pt` and writes EMU only (Office writes only EMU, OI §2.1.1319 b).
**D-D05:** a range written with `addImage` that ends in the last column or row (XFD, 1048576) cannot use the exclusive `to` marker (16384 / 1048576 exceed the [MS-OI29500] maxima); the marker is then the last column or row with an offset of its full width or height in EMU (TD-33 pixels). LibreOffice 24.2.7.2 opens such a file and keeps the pictures, placing those at the grid edge by its own sizes (observed 2026-10-30). A size that rounds to 0 EMU is refused.

### TD-33 - EMU and pixels - VERIFIED (EMU) / PROVISIONAL (pixels)
P1 §20.1.2.1: 1 EMU = 1/914400 inch = 1/360000 cm; §20.1.10.35: 1 pt = 12700 EMU (R3 Item 13). **Per pixel: NOT FOUND**; P1 §20.1.2.2 forbids pixels as a unit in the format. xlvane's API takes pixels at 96 per inch (9525 EMU per pixel), a convention that matches exceljs (`ext-xform.js`, 9525 EMU/px). Fractional positions use pixel sizes of cells: a column of stored width `w` is `round(w × 7)` pixels (W2-03: the width includes the padding, in characters of the 7-pixel maximum digit width of Calibri 11), a column without width 64 pixels (Excel's default column, observed), a row of `h` points `round(h × 96 / 72)` pixels, a row without height 20 pixels (15 points, the `defaultRowHeight` xlvane writes). The streaming writer assumes default row heights. LibreOffice 24.2.7.2 writes a default column as 611 280 EMU and a default row as 190 080 EMU (TD-39).

### TD-34 - Order in the worksheet - VERIFIED
CT_Worksheet (`sml.xsd` T2165–2213): … `hyperlinks`, `printOptions`, `pageMargins`, `pageSetup`, `headerFooter`, `rowBreaks`, `colBreaks`, `customProperties`, `cellWatches`, `ignoredErrors`, `smartTags`, `drawing` (T2202), `legacyDrawing` (T2203), `legacyDrawingHF`, `drawingHF`, `picture` (T2206), `oleObjects`, `controls`, `webPublishItems`, `tableParts` (T2210), `extLst`.

### TD-35 - Picture markup - VERIFIED (schema) / Annex L pattern
CT_Picture (`dml-spreadsheetDrawing.xsd` L60): `nvPicPr` (`cNvPr`, `cNvPicPr`), `blipFill`, `spPr` required; CT_NonVisualDrawingProps (`dml-main.xsd` L810): `id` and `name` required, `descr`, `hidden`, `title`, children `hlinkClick`, `hlinkHover`, `extLst`; CT_BlipFillProperties L1524 (`blip`, `srcRect`, fill mode), CT_Blip L1497 (`r:embed`, `r:link`), CT_ShapeProperties L2245 (all children optional). `cNvPr@id` is unique "within the current document", which is not defined (R3 Item 13); xlvane numbers the pictures of each drawing from 1. `a16:creationId`: its extension URI and uniqueness rules were NOT FOUND in [MS-ODRAWXML] (R3 Item 16), so xlvane writes none (exceljs writes one constant GUID for every picture). Written form: `xdr:pic` with `a:blip r:embed`, `a:stretch/a:fillRect` and `a:prstGeom prst="rect"`, as in P1 Annex L picture examples; one image relationship per image and drawing.
**D-D05:** `name` (`cNvPr@name`) and `descr` are xsd:string, so characters XML 1.0 cannot carry (C0 controls other than tab, LF and CR; U+FFFE; U+FFFF; lone surrogates) are refused; tab, LF and CR are kept. A picture hyperlink is a relationship target (a URI): all C0 controls, DEL, U+FFFE and U+FFFF are refused.

### TD-36 - Sheet background - VERIFIED
`picture r:id` (P1 §18.3.1.67, P4 §15.10.15, R3 Item 11): a relationship of type `…/relationships/image` from the worksheet to the background image.

### TD-37 - Picture hyperlinks - PARTLY
`cNvPr/a:hlinkClick r:id` → a `hyperlink` relationship of the Drawings part (§12.3.8 permits Hyperlinks). The only clause for hlinkClick is §21.1.2.3.5 (written for text runs); there is no DrawingML clause for the hlinkClick of cNvPr (R3 Item 13). OI §2.1.1359: Excel does not support `hlinkHover`. xlvane reads the target as text, never opens it, and writes external targets with `TargetMode="External"`.

### TD-38 - Pictures when rows are inserted or deleted - IMPLEMENTATION (PROVISIONAL)
No document states how markers move. xlvane moves each `from`/`to` marker row as a range end moves (R-03, R-08): a marker at or below the first inserted row moves down, so a picture that contains the insertion grows; one-cell anchors move with their cell; absolute anchors stay. A deletion that would remove a row a picture covers (or its one-cell anchor row) is refused (`XLV_E_NOT_SUPPORTED`), and so are drawings with objects other than pictures. `editAs` is not interpreted. POI corpus: insert-then-delete gives the original anchors back for every picture-only drawing.
**D-D05:** a `to` marker with no row offset that lies on the boundary below the picture (the start of the row after its last row) moves only when rows are inserted at or above that last row, so rows inserted directly below a picture leave it unchanged, as LibreOffice 24.2.7.2 does (review observation). The anchors are located with the element scanner, linear in the size of the drawing part; anchors without a picture, empty anchors and other children of `wsDr` are refused.

### TD-39 - LibreOffice 24.2.7.2 - OBSERVED
A file written by xlvane with a PNG over B2:D6 (`to` = E7 + 0) and a JPEG with `editAs="oneCell"` is re-saved by LibreOffice with both images byte for byte, the description and `editAs`; LibreOffice writes the bottom-right corner as an offset inside the last covered cell (D6 + 611 280 EMU, 190 080 EMU) instead of the start of the next cell. `tests/libreoffice/images.test.ts`.
