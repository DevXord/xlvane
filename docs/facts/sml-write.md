### W2-02 — Cells and formulas
CT_Cell is the sequence `f`, `v`, `is`, `extLst` with attributes `r`, `s` (default 0), `t` (default `n`) (S-XSD L2274; agrees with E-20 … E-23). CT_CellFormula extends `ST_Formula`, which restricts `s:ST_Xstring` (S-XSD L216–218, L2751), so formula text uses the `_xHHHH_` escape like other ST_Xstring values (F-XS-01). PROVISIONAL for ST_Formula only; the reader now decodes formula text accordingly.
**Verified (2026-10-30):** `sml.xsd` (Part 4 schema archive) ST_Formula L216–218 (`restriction base="s:ST_Xstring"`), CT_CellFormula L2751 (simpleContent extension of ST_Formula), CT_Cell L2274. ST_Formula is no longer provisional.

### W2-03 — `cols` / `col` — VERIFIED (unit corrected 2026-10-30)
CT_Cols holds 1..n `col`. CT_Col attributes: `min`, `max` (unsignedInt, required), `width` (double), `style` (default 0), `hidden`, `bestFit`, `customWidth`, `phonetic` (boolean, default false), `outlineLevel`, `collapsed`. Source: S-XSD L2233–2252. **Not checked:** the unit of `width` (the writer passes the caller's number through and documents it as "characters", as in Excel's column width box) and whether `customWidth="1"` is needed for a width to apply.
**Verified:** `sml.xsd` (Part 4 schema archive) CT_Cols L2233–2237, CT_Col L2238–2252. The unit of `width` and the role of `customWidth` are prose in Part 1 §18.3.1.13 (not supplied).
**Checked 2026-10-30 (D-1101, D-1104), corrects the unit:** `col@width` is in characters of the maximum digit width of the Normal font, including 5 px padding, truncated to 1/256: `Truncate([{Number of Characters} * {Maximum Digit Width} + {5 pixel padding}]/{Maximum Digit Width}*256)/256`. With Calibri 11 (maximum digit width 7 px), 8 characters are stored as 8.7109375. Source: ECMA-376 Part 1 §18.3.1.13, p.1601–1602. Office requires 0 ≤ width ≤ 255 ([MS-OI29500] rev. 25.0 §2.1.598 c, p.253). `customWidth` is not stated as required for `width` to apply. xlvane writes the caller's value unchanged, rejects values outside 0–255, and its TSDoc no longer calls the value the number in Excel's column-width box.

**Column style (2026-10-30, D-A04):** CT_Col `style` is `xsd:unsignedInt`, optional, default `0` (sml.xsd L2242); `width` is optional (L2241), so a `col` with only `style` is valid. [MS-OI29500] rev. 25.0 §2.1.598 d, p.253: Office requires `style` 0 … 65429, which the cellXfs count limit (65430, D-1101) already guarantees. The writer writes `style` only when it is not 0 and never applies a column's style to its cells. **Checked 2026-10-30 (second local report, item 5):** ECMA-376 Part 1 §18.3.1.13 `col`, attribute `style`, p.1601 (`pdftotext -layout` L75432–L75433): the default style for the affected column(s); it "Affects cells not yet allocated in the column(s)". The clause does not name the collection the index points into (cellXfs is not mentioned in §18.3.1.13 or §18.3.1.17). `editCells` therefore starts a cell it creates from the column's `style` when that index exists in `cellXfs`; existing cells keep their own format. The sources do not say whether a row format (`row@s` with `customFormat`) or the column style wins for a new cell, so in such a row the earlier behaviour (format 0) is kept (D-A04).

### W2-07 — `t` and `xml:space`

### W2-08 — Sheet names in formulas — VERIFIED
The `_xlnm._FilterDatabase` value quotes the sheet name with apostrophes and doubles apostrophes inside it. **Not checked** in the formula grammar (Part 1 §18.17); LibreOffice accepted names with `&`, `<`, spaces and apostrophes in the test.
**Checked 2026-10-30 (D-1104):** ECMA-376 Part 1, 5th ed. (2016) §18.17.2.3, p.2049–2051: `work-sheet-prefix-special= apostrophe, sheet-name-special, apostrophe, "!" …`, `sheet-name-character-special= apostrophe, apostrophe | character – (apostrophe | "*" | "[" | "]" | "\" | ":" | "/" | "?")`; unquoted names exclude operators, apostrophe, `[`, `]`, `\`, `?`. Quoting any name is valid. [MS-OI29500] rev. 25.0 (2026-08-18) §2.1.863 a, p.392 and [MS-XLSX] rev. 30.0 (2026-10-16) §2.2.2, p.39 agree and also exclude U+0003 in quoted names; a quoted 3-D prefix has one pair of apostrophes (`'Sheet 1:Sheet 3'!A1`).

### W2-42 — `hyperlinks` / `hyperlink` — VERIFIED
CT_Hyperlinks holds 1..n `hyperlink`; CT_Hyperlink has `ref` (ST_Ref, required), `r:id`, `location`, `tooltip`, `display` (ST_Xstring), all optional, no defaults. `hyperlinks` is optional, at most once, after `dataValidations` and before `printOptions` in CT_Worksheet, so after `mergeCells`. Sources: Transitional `sml.xsd` L2739–2750 and L2191, Strict L2718–2729 and L2175; ECMA-376 Part 1 §18.3.1.47 p.1641–1642 (L77389–77425), §18.3.1.48 p.1642 (L77427–77443): `r:id` is "the relationship Id in this sheet's relationships part that expresses the target location of the resource"; `location` "shall refer to a sheet and cell or a defined name" when the target is this workbook, or an anchor inside the target; `tooltip` is hover text; `display` is the display string if it differs from the cell text. Annex L.2.13.10–11 (informative, p.4754–4755): the cell text is the link's "friendly" name. Not stated (report 2, item 1): that `r:id` is omitted for a link inside the workbook. xlvane writes such a link with `location` only; LibreOffice 24.2.7.2 does the same when it re-saves the file (tests/libreoffice/hyperlinks.test.ts). `ref` may be a range; nothing says how a range applies to its cells, so the reader attaches the link to every existing cell of the range (D-A08).

### W2-43 — Hyperlink limits — VERIFIED
[MS-OI29500] rev. 25.0 §2.1.626 a–c, p.263: Office requires `location` and `display` to be 0 … 2084 characters and `tooltip` at most 255 characters. No limit on the number of hyperlinks was found (report 2, item 10 A). xlvane enforces these three and, for the external `url`, its own limit of 65 536 characters (implementation choice).

### W2-44 — Hyperlink relationship — VERIFIED
An external target is a relationship of the worksheet part with `TargetMode="External"` and the URL in `Target` (Part 1 §15.3 p.161–162, L7924–7947, and the examples in §18.3.1.48 and Annex L.2.13.11). Type: Transitional `http://schemas.openxmlformats.org/officeDocument/2006/relationships/hyperlink` (Part 4 §13.3 p.29, part4.txt L1866), Strict `http://purl.oclc.org/ooxml/officeDocument/relationships/hyperlink` (Part 1 §15.3, L7926). A Worksheet part may have explicit relationships to Hyperlinks (Part 1 §12.3.24, L4908–4918). Part 4 §15.10.10 (p.224): in Transitional files `r:id` is in the `…/officeDocument/2006/relationships` namespace. The relationships part of `xl/worksheets/sheetN.xml` is `xl/worksheets/_rels/sheetN.xml.rels` (Part 2 Relationships part naming, docs/facts/opc.md F-OPC-02, F-OPC-07); its content type comes from the `rels` Default entry (W2-30).

### W2-45 — Comments part content (`comments`) — VERIFIED
CT_Comments is `authors` (1, holding 0..n `author`, ST_Xstring), `commentList` (1, holding 0..n `comment`) and optional `extLst`. CT_Comment has `text` (CT_Rst, required), optional `commentPr`, and the attributes `ref` (ST_Ref, required), `authorId` (unsignedInt, required, 0-based index into `authors`), `guid` and `shapeId` (optional). Sources: Transitional `sml.xsd` L272–316, Strict L263–307 (identical); ECMA-376 Part 1 §18.7 … §18.7.7, p.1745–1752 (report 2, item 2). Rules used: `ref` is a single cell (§18.7.3); each comment has an author, author names are unique per sheet (§18.7.1, §18.7.2); `text` is rich text (§18.7.7). [MS-OI29500] rev. 25.0: Excel fails to open a file with `commentPr` (§2.1.691 a), ignores `shapeId` (§2.1.690 b), `guid` is optional outside shared workbooks (§2.1.690 a), author at most 65 535 characters (§2.1.689 a), text via `t` at most 32 767 characters and `r` at most 32 767 times (§2.1.692 → §2.1.678 b, §2.1.630 a). No limit on the number of comments or authors was found. **xlvane:** writes neither `commentPr`, `guid` nor `shapeId`; writes an author `""` when none is given (an author is required); reads a comment whose `authorId` names no author with `author: null` and a warning, and skips a `ref` that is not a single cell with a warning.

### W2-46 — Comments part and relationship — VERIFIED
Content type `application/vnd.openxmlformats-officedocument.spreadsheetml.comments+xml`, root `comments`, one part per worksheet that has comments, reached by an **implicit** relationship of type `http://schemas.openxmlformats.org/officeDocument/2006/relationships/comments` (Transitional, Part 4 §10.2.3 p.18) or `http://purl.oclc.org/ooxml/officeDocument/relationships/comments` (Strict, Part 1 §12.3.3 p.70–72, L3341–3414), TargetMode Internal, no outgoing relationships. §12.3.3 names the Workbook part as the source, but its own example, §12.3.24 (L4901), §18.7.6 and Annex L.2.6.3 put the relationship on the worksheet; xlvane follows the worksheet (report 2, item 3a). [MS-OI29500] §2.1.6 b: Office does not allow a Comments part from chartsheets or dialogsheets. Threaded comments ([MS-XLSX] rev. 30.0 §2.1.17 p.35, §2.3.7 p.105) are a separate part (relationship `http://schemas.microsoft.com/office/2017/10/relationships/threadedComment` from the worksheet); for each thread Excel stores a legacy placeholder comment whose author "MUST contain \"tc={uid}\"" (§2.3.7.3 p.106). xlvane reads the placeholders as notes and reports the threads with `XLV_W_THREADED_COMMENTS`.

### W2-47 — VML Drawing part and the note shape — VERIFIED / example-based
Part 4 §8.2 p.13–14: content type `application/vnd.openxmlformats-officedocument.vmlDrawing`, root `xml` in no namespace, explicit relationship `http://schemas.openxmlformats.org/officeDocument/2006/relationships/vmlDrawing` from a worksheet, TargetMode Internal; the part exists only in Transitional (not in Part 1 or the Strict schema). [MS-OI29500] §2.1.1754 a: the part "closely resembles XML". A note is a `v:shape` containing `x:ClientData ObjectType="Note"` (Part 4 §19.4 p.829–830; `vml-spreadsheetDrawing.xsd` CT_ClientData, every child optional, only `ObjectType` required). `x:Row` and `x:Column` are 0-based (§19.4.2.50, §19.4.2.15); `x:Anchor` is `LeftColumn, LeftOffset, TopRow, TopOffset, RightColumn, RightOffset, BottomRow, BottomOffset` (§19.4.2.3), and Office requires 8 non-negative integers ([MS-OI29500] §2.1.1857 c); without `x:Visible` the note is hidden (§19.4.2.65). Boolean children without a value mean true (each element's clause; [MS-OI29500] §2.1.1894); Excel reverses MoveWithCells/SizeWithCells (§2.1.1881, §2.1.1886). **NOT FOUND:** which children a consumer needs to show a note, and a normative link between a comment and its shape (report 2, items 2 and 12). **xlvane follows the examples exactly:** the `x:ClientData` children of the Part 4 §19.4 example (MoveWithCells, SizeWithCells, Anchor, AutoFill False, Row, Column) without `x:Visible`; `fillcolor="#ffffe1"`, `v:fill`, `v:shadow`, `v:path`, `v:textbox` as in that example; the `v:shapetype` `_x0000_t202` with `o:spt="202"`, and the anchor pattern (`col+1, 15, row−1, 10, col+3, 15, row+3, 4`, rows clamped at 0) of Part 1 Annex L.5.5.2 (informative, L263491–263545). The CSS `style` (`position`, `margin-left`, `margin-top`, `width`, `height`, `z-index`, `visibility`; Part 4 §19.1.2.19 `style`, p.598–601 of the container's Part 4 text L29493–29747) is computed for the default 64 px columns and 20 px rows, which reproduces the Annex L.5.5.2 values (107.25pt, 52.5pt, 96pt, 55.5pt for B5). Shape ids: `o:idmap` (Part 4 §19.2.2.14, p.736–737) is optional and its `data` is application-defined; xlvane uses blocks of 1024 ids per part as in the examples (`data="1"` with `_x0000_s1025` in §19.4, `_x0000_s1027` in Annex L.5.5.2), one block more per 1024 notes, and different blocks per sheet. LibreOffice 24.2.7.2 re-saves such files with the notes (tests/libreoffice/notes.test.ts).

### W2-12 — Font 0 is the default font — VERIFIED
The writer puts the default font (Calibri 11) at index 0 and the reader treats `fontId="0"` as "default". This is how Excel and LibreOffice files are laid out (the cell style "Normal" uses `xfId 0` → font 0), **not checked** in §18.8.
**Supporting evidence (not a normative rule):** in `presetCellStyles.xml` (Part 1 supporting archive) the `normal` preset's style sheet has the default font first and `cellStyle Normal` with `xfId="0"`, whose xf uses font 0. The rule itself still needs Part 1 §18.8 or [MS-OI29500].
**Checked 2026-10-30 (D-1104):** ECMA-376 Part 1, 5th ed. (2016) §18.4.3 phoneticPr, attribute `fontId`, p.1722: if the index is out of bounds the default font of the Normal style should be used, and this default font should be at index 0.
