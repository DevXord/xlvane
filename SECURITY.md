# Security policy

xlvane opens spreadsheet files from unknown sources, so every input file is treated as untrusted.

## Reporting a vulnerability

Please report vulnerabilities privately through GitHub private vulnerability reporting: on the repository page open the **Security and quality** tab and choose **Report a vulnerability**. Please do not open a public issue for a security problem.

A useful report contains the xlvane version (or commit), the runtime (Node.js, Bun, Deno, browser, Workers) and, if possible, a file or a script that reproduces the problem. The maintainer will acknowledge the report and agree on a disclosure timeline with you.

## Supported versions

Security fixes are released for the newest minor version of `xlvane`, `@xlvane/compat` and `@xlvane/mcp` (currently 1.3.x; the three packages share one version); please update to it. Releases are published from GitHub Actions with npm provenance: `xlvane` and `@xlvane/compat` since 1.0.1, `@xlvane/mcp` since 1.2.2 (1.2.0 and 1.2.1 were published from the maintainer's machine, docs/decisions.md D-I03 and D-I07). The changes are listed in [CHANGELOG.md](CHANGELOG.md).

## What the library defends against

| Area | Protection |
|---|---|
| ZIP | Limits on the number of entries, on the decompressed size of each entry and of all entries read, and on the compression ratio. Sizes are measured on the bytes actually decompressed, not taken from ZIP headers. Overlapping entries, duplicate entry names, encrypted entries, unsupported compression methods and multi-disk archives are rejected. CRC-32 is verified. |
| XML | Own parser. Document type declarations (DTDs) are rejected, which rules out external entities (XXE) and entity expansion ("billion laughs"). Only the five predefined entities and character references are recognised. Limits on nesting depth, name length, attribute count and text length. The parser is iterative, so deep nesting cannot overflow the call stack. |
| Data | Inside the library, values read from a file never become keys of plain objects: lookups use `Map` or arrays, so names such as `__proto__`, `constructor` and `prototype` cannot change any object prototype. The row objects of `readTable`, `readTableStream` and `toJSON` are keyed by the header text of the file; their properties are defined with `Object.defineProperty`, so a header `__proto__` is an ordinary property, but code that copies such rows (for example `Object.assign`) or calls methods on them (such as `row.hasOwnProperty`) should treat the keys as untrusted. |
| Amplification | Work derived from a small file is bounded, not only the file itself: output positions of `toCSV`, `readTable`, `toJSON` and `readTableStream` (at most `maxCells` or 16 times the cells read), cells created by `@xlvane/compat` for merged ranges, tables and columns, hyperlinks resolved to cells, the expanded text of shared formulas, a sheet part shared by several sheets (read once), the characters of header names repeated in every row object, the cells written by `fromCSV`, `fromJSON` and `writeTable`, the cells `editCells` and `appendRows` work on (the edited sheets plus new cells, before any cell is built) and the cell formats `insertRows` copies, the shared-formula text `@xlvane/compat` moves when `cell.formula` is read, and the cells one row element may hold while streaming. `@xlvane/compat` also bounds the cells of defined names and data validations created on load, and the input it collects from a stream. Parsing, streaming from a `Blob`, row changes, editing cells, notes, pictures, header detection, sheet, merge and name lookups while writing, and reading style-only cells run in time linear (or near-linear) in the input; tests check worst-case inputs (docs/decisions.md D-H01, D-J01, D-K04). |
| Regular expressions | Untrusted text is parsed by hand-written scanners instead of backtracking regular expressions; tests check worst-case inputs. |
| Charts | Chart parts are read only for charts in worksheet drawings: parsed under the XML limits, their cached and literal values not built into a tree, their series and chart groups counted against what the cells leave of `maxCells`, and a part that is over a per-part limit, not a chart part or malformed is skipped with a warning. A chart part shown by several frames, and a drawing part shared by several sheets, is read once. Series and title references are text: they are never evaluated or followed. `writeWorkbook` limits the cached values it writes (4 000 000 cells, 8 388 608 characters of text). |
| CSV export | `toCSV`, `xlvane convert` and `workbook.csv` of `@xlvane/compat` write text that starts with `=`, `+`, `-`, `@`, a tab, CR or LF, the full-width `＝`, `＋`, `－`, `＠`, or (as a precaution) another control character or the small `﹦`, `﹢`, `﹣`, `﹫`, with a leading `'`, so spreadsheet applications show it as text instead of running it as a formula (OWASP CSV Injection; docs/facts/csv.md CSV-10, CSV-12). While text is escaped, options that would get around the escape are refused: a delimiter that starts a formula, and in `@xlvane/compat` an escape character other than the quote or a field starting with `"` without the default quote; `latin1` output writes characters above U+00FF as `?` before the fields are checked (CSV-13). A byte order mark before a formula sign counts as a formula start, also as bytes in `latin1` and `utf16le` output, and values returned by a `map` function are checked as the text written (D-K03). Fields holding `,`, `;`, a tab or `|` are quoted whatever the delimiter (CSV-14); a reader that splits on another separator than the writer used can still take such a field apart, so write with the separator the reader expects. `formulaInjection: "off"` writes the text unchanged. |
| Command line | `xlvane migrate` does not follow symbolic links (also not a `package.json` that is one) and changes only the `exceljs` entry of the dependency sections. Human-readable output shows text from files with control and bidirectional characters escaped and line feeds as `⏎`, so a cell, sheet name or title cannot move the cursor, change the window title, add colours, add lines or reorder the output. `--json` prints the same data, with control and bidirectional characters as `\uXXXX` escapes. Files are never replaced without `--force`; a replacement goes through a temporary file with a random name, readable only by the owner until it gets the permission bits of the replaced file (without setuid, setgid or sticky bits). |
| MCP server (`@xlvane/mcp`) | Tools read and write only inside the `--root` directories: real paths are checked after symbolic links are followed (a path is walked as the system resolves it, and one whose links pass through a directory outside the roots is refused even when it ends inside, so a link inside a root does not reveal what exists outside), a file is checked again after it is opened (same device and inode), writes create files exclusively or replace them through a temporary file only with `"overwrite": true`, and the write tools exist only with `--allow-write`. Files are limited in size (`--max-file-size`, also the JSON text `convert` builds), workbooks in cells (`--max-cells`, also the cells a write or edit request holds) and tool results in length (`--max-response-chars`); stderr shows control characters as `\uXXXX`. Cell text is returned as data and may contain any text, including text written to influence a model; the server does not interpret it. A local process that can change the root directories while the server runs can still race a write (the directory of a new file is checked before writing). |

All limits can be changed by the caller; the defaults are documented in the package README.

## Out of scope

- xlvane does not evaluate formulas. Cached formula results are returned as stored in the file.
- Macros (VBA projects) are never executed. `inspect()` reports their presence.
- External links are never followed. `inspect()` reports their presence.
- Password-protected (encrypted) workbooks and legacy `.xls` files are not supported and are rejected with an error.
